# 位置任务功能设计

## 概述

用户A可以向用户B发送一个"位置任务"，指定一个地理坐标和范围。当用户B进入该区域时，App弹出提示通知。

本功能是App首个多用户协作特性，需要引入用户身份体系、云端数据同步和远程推送能力。

---

## 核心概念

### 位置任务（LocationTask）

一个位置任务包含：
- 发送者：创建任务的用户
- 接收者：需要到达指定位置的用户
- 目标区域：坐标 + 半径
- 任务描述：发送者填写的文本说明
- 状态：待触发 / 已触发 / 已过期

### 用户关系

- 用户之间通过"邀请码"建立连接，无需好友列表等社交关系
- 发送任务时，输入对方的邀请码即可投递

---

## 用户身份

### 方案：匿名身份 + 邀请码

为保持App隐私优先的设计理念，不引入注册/登录流程：

- App首次启动时，自动生成一个本地唯一标识（UUID）
- 同时生成一个**6位邀请码**（大写字母+数字），作为用户对外的可读标识
- 邀请码与UUID的映射关系存储在云端
- 用户可在设置页查看和分享自己的邀请码

### 用户标识数据

```
UserIdentity {
    id: UUID            // 设备唯一标识
    inviteCode: String  // 6位邀请码，如 "A3K9X2"
    deviceToken: String // APNs推送令牌
    createdAt: Date
}
```

---

## 数据模型

### LocationTask

```
LocationTask {
    id: UUID
    senderId: UUID          // 发送者ID
    senderCode: String      // 发送者邀请码（用于接收者显示）
    receiverId: UUID         // 接收者ID
    title: String           // 任务标题
    description: String?    // 任务描述（可选）
    latitude: Double        // 目标纬度
    longitude: Double       // 目标经度
    radius: Double          // 触发半径（米），默认1000
    status: TaskStatus      // pending / triggered / expired
    expiresAt: Date?        // 过期时间（可选）
    createdAt: Date
    triggeredAt: Date?      // 实际触发时间
}
```

### TaskStatus

```
enum TaskStatus {
    case pending    // 等待接收者进入区域
    case triggered  // 已触发通知
    case expired    // 已过期
}
```

---

## 云端服务

### 技术选型：CloudKit

选择CloudKit作为后端方案，理由：
- Apple原生服务，无需额外后端部署和维护
- 免费额度满足小规模使用
- 与iOS推送体系天然集成
- 符合Apple隐私规范

### 数据存储

使用CloudKit Public Database存储：
- `UserIdentity` 记录：邀请码 <-> UUID映射
- `LocationTask` 记录：任务数据

### 推送机制

使用CloudKit Subscription + APNs：
- 当新的`LocationTask`记录被创建且`receiverId`匹配当前用户时，CloudKit自动推送静默通知
- App收到静默通知后，拉取任务详情，注册本地地理围栏

## 流程设计

### 发送任务流程

```
用户A操作：
1. 进入"发送位置任务"页面
2. 输入接收者的邀请码
3. 在地图上选择目标位置（复用现有LocationReminderPickerView）
4. 设置触发半径（默认1km）
5. 填写任务标题和描述
6. 可选：设置过期时间
7. 点击发送

系统处理：
1. 根据邀请码查询接收者UUID
2. 创建LocationTask记录写入CloudKit
3. CloudKit触发推送通知给接收者设备
4. 向发送者显示"发送成功"
```

### 接收任务流程

```
用户B设备：
1. 收到CloudKit静默推送
2. App从CloudKit拉取新任务数据
3. 缓存任务到本地（SwiftData）
4. 注册CLCircularRegion地理围栏监控
5. 任务出现在"收到的任务"列表中

触发流程：
1. 用户B进入目标区域
2. 系统触发didEnterRegion回调
3. 弹出本地通知："来自[发送者邀请码]的位置任务 - [标题]"
4. 更新任务状态为triggered
5. 同步状态到CloudKit（发送者可查看）
6. 移除该地理围栏监控
```

### 过期处理

- 如果设置了过期时间，到期后自动标记为expired
- 移除对应的地理围栏监控
- 后台任务定期清理过期任务

## 页面设计

### 新增页面

#### 1. 设置页 - 我的邀请码

- 显示当前用户的6位邀请码
- 提供复制和分享按钮
- 首次进入时自动生成并上传至CloudKit

#### 2. 位置任务列表页

入口：首页新增Tab或菜单项"位置任务"

分为两个Tab：
- **收到的任务**：别人发给我的任务列表
- **发出的任务**：我发给别人的任务列表

每个列表项显示：
- 任务标题
- 对方邀请码
- 状态标签（待触发 / 已触发 / 已过期）
- 创建时间

#### 3. 发送位置任务页

表单字段：
- 接收者邀请码：文本输入，6位
- 任务标题：文本输入，必填
- 任务描述：多行文本，选填
- 目标位置：地图选择器（复用现有组件）
- 触发半径：滑块，范围200m~5000m，默认1000m
- 过期时间：日期选择器，选填

#### 4. 任务详情页

显示：
- 任务完整信息（标题、描述、位置、半径）
- 地图预览（标注目标区域）
- 当前状态及状态变更时间线
- 发送者/接收者邀请码

## 与现有功能的关系

### 复用

- **地图选择器**：复用`LocationReminderPickerView`的地图选点能力
- **地理围栏监控**：复用`LocationService`的围栏注册和回调机制
- **本地通知**：复用`NotificationService`的通知发送能力

### 隔离

- 位置任务的地理围栏与计数器提醒的地理围栏**独立管理**，使用不同的regionId前缀区分（如`task_`前缀 vs 现有`ticca_`前缀）
- 位置任务数据使用独立的SwiftData模型，不与Counter模型耦合

### 地理围栏数量限制

iOS限制每个App最多同时监控20个地理围栏。需要统一管理：
- 计数器提醒围栏 + 位置任务围栏共享20个配额
- 当配额不足时，优先保留计数器提醒围栏，位置任务按创建时间排队
- 在任务列表中提示用户当前围栏使用情况

## 权限要求

在现有权限基础上，新增：
- **后台刷新**（Background Fetch）：用于接收CloudKit静默推送后拉取数据
- **远程推送**（Remote Notifications）：接收CloudKit Subscription推送

现有已具备：
- 位置权限（Always）
- 本地通知权限

## 阶段规划

### 第一阶段：基础能力

- 用户身份生成与邀请码体系
- CloudKit数据模型与读写
- 发送/接收任务的基本流程
- 地理围栏触发与通知

### 第二阶段：体验优化

- 任务状态同步（发送者可看到接收者是否已触发）
- 过期自动清理
- 围栏配额管理策略

### 第三阶段：扩展（可选）

- 支持给任务附加图片
- 任务触发后的互动回复
- 常用联系人（记住邀请码）
